The Home panda — daily poses & state machine brief

Home is where the panda lives most of the time: one big card, the panda in a pose with a line of text under it, and “Tap me when you need me” beneath that. This brief covers the eight daily poses, what happens on a tap, and how the Rive file is wired so the app can pick the day's pose. Same two-part shape as the SOS brief.

One change from round one: the card no longer cycles a new pose every few seconds. It shows one pose per day. Slower, calmer, and the pose becomes “today's panda”.

1Animation — the eight daily poses

Each day the app picks one of eight pose-and-line pairings and holds it all day. The pose has to read on its own — the text sits below it and might not be read at all. Round one's composition rules still apply: square-ish framing, panda centred, nothing important near the edges.

Each pose is a living still, not a performance

  • Every pose gets a gentle idle loop: slow breathing on roughly a 4-second cycle, an occasional blink, maybe a tail settle. That's the whole budget.
  • Home has other things on it that matter more — the help button most of all. The panda must feel alive, never busy. If in doubt, do less; easing to near-still after a handful of cycles is a welcome option.
  • The comedy lives in the pose itself, not the motion. Pose 06 is mid-yell as a held pose — it does not actually yell on loop.

On tap — the panda answers

The whole card is the tap target, and tapping it opens the “How are you feeling?” screen. The app handles the card press (a gentle lift) and the navigation. What I want from you is the panda's part: a small acknowledgement the moment it's touched — the panda noticed you before the screen changes.

  • One short reaction per pose, in character for that pose: the box-hider peeks further out, the keeled-over one lifts its head, the yeller takes a breath. Your call on each — these are suggestions.
  • Fast and small: well under a second, no anticipation wind-up. It plays while the next screen is already arriving, so the first few frames are the ones that count.
  • After the reaction, back to the idle without a visible jump.
  • This is the same job as the ear-twitch triggers in the current character file — a poke from outside, a flicker of life in response.

Not in this brief

  • The four feeling illustrations on the “How are you feeling?” screen — round one, unchanged, still stills.
  • The “Play with red panda” sit-and-pet screen — that's its own piece of work and its own brief, once these poses are settled.
  • All text, the card itself, buttons, navigation — the app's job. You draw only the panda.

2State machine management

Same contract as the SOS file: the app loads the file, binds its view model, and drives it through named inputs. Here the machine is much simpler — one number picks the day's pose, one trigger pokes it.

The shape of it

Entry → pose 0–7 Pose idle ⇄ Tap reaction · one-shot

Eight idles, each with its own reaction. The number decides which one; the trigger works on whichever pose is showing.

The inputs

Proposed names — same warning as before: these go into the app's code, so flag any change before the file ships, and please keep everything in plain English.

NameTypeWhat it does
posenumber 0–7Which daily pose shows, numbered as the table above (01 = 0 … 08 = 7). Set once, before play. Out-of-range values should land on pose 0, not on nothing.
poketriggerThe tap reaction for whichever pose is showing.

Transition rules

FromToWhenRule
EntryPose idleon loadStraight in, by pose. No entrance animation needed — the app fades the card in itself.
Pose idleReactionpokeFrom any frame of the idle, immediately — no waiting for a loop boundary here, the whole point is instant response.
ReactionSame pose idleautomaticallyBlend back smoothly; the idle should not visibly restart.

Pokes don't stack. Someone anxious will tap three times fast. A poke that lands mid-reaction is simply ignored — the reaction finishes and returns to the idle. No queueing, no restarting, and definitely no speeding up, which would read as the panda getting agitated.

The pose never changes on screen. The day's pose is set before play and stays. There is no on-screen morph from one pose to another to build — if the app ever changes pose mid-play, a hard cut is acceptable, because it should never happen where anyone can see it.

Same three constraints from the app

  1. First frame of every pose works as a still — “reduce motion” freezes each state on frame one, so all eight opening frames are posters.
  2. Idles loop seamlessly for minutes. Home can sit open a long time. No drift, no seam, no tic on the tenth repeat.
  3. No Rive listeners. The app detects the tap and fires poke from outside. Don't wire pointer events in the file.

House rules carry over too: English names throughout, and a written list shipped with the file of every artboard, state machine and input name, spelled exactly. Whether these poses live in the same .riv as the SOS work or their own file is your call — the app selects by name either way, so the list is what matters.

Phasing

Same rhythm as round one: pick the three poses you'd most like to make and start there, with the pose and poke wiring in place from the first file. We review the three, settle the motion budget together, and then you take it to all eight — the remaining five should be additive, not a rebuild.

✓How I'll check the file

  • Set pose to each of 0–7: the right pose shows, and its first frame reads as a good still.
  • Set pose to 9: pose 0 shows — not a blank artboard.
  • Let each idle run five minutes: seamless, calm, nothing that becomes a tic.
  • Fire poke once on each pose: an in-character reaction, under a second, smooth return to the idle.
  • Fire poke five times fast: one clean reaction, no pile-up, no acceleration.
  • Every name matches the shipped list, letter for letter.
  • All eight poses read on the light card and on dark #1B2418.

Tell me which three poses you're starting with when you send the first file across, and shout early if any of the eight lines suggests a completely different pose to you than my sketch does — the line wins, not the sketch.
